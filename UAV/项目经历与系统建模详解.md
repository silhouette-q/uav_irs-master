# 第一部分 · 项目经历

## 1.1 起点与研究定位

**长期方向**：GDM-DRL（生成式扩散模型 + 深度强化学习）用于无线通信资源管理。
**已有基础**：本科毕设《基于生成式强化学习的通信、感知与充电一体化网络优化》，提出 **GD-MAPPO**
（扩散策略网络替代高斯策略 + MAPPO + CTDE + 自适应奖励中心化），应用于多无人机 ISCC 场景。
**本项目定位**：导师指定一篇可 follow 的论文，走完「读懂 → 复现建模 → 扩展场景 → 迁移毕设方法求解」的完整链路。

**目标论文的问题**：边缘服务器显存有限、LLM 请求稀疏突发。空闲时把模型层留在显存则响应快但持续占显存；
卸载则省显存但下次请求要重新加载（7B 模型满载加载约 4.8 秒）。论文按**层粒度**决定"哪些层、何时卸载"，
在内存成本与加载延迟间权衡并满足 QoS。**方法是 ski-rental + 拉格朗日对偶，不是 DRL** —— 这正是我们要用 DRL 替代/增强的对象。

## 1.2 五个阶段

### 阶段一：论文公式精读（起点 2026-07-06）

把论文第四节（在线算法设计）A→H 全部公式链条读通：

| 小节 | 内容 | 关键产出 |
|---|---|---|
| A | 系统建模 | 层参数 c_i / d_i，决策变量 t_i，保留状态 s_i，C_i 递增 / D_i 递减 |
| B | 目标与约束 | QoS 定最少常驻层 ī（式 1a），总目标（式 2a） |
| C | 化简成 ski-rental | 假设 d=kc ⇒ 多斜率压成 2-斜率，临界点 B，可卸层同时刻卸 |
| D | 随机化策略 | P(t) = p(t) + αδ(t) + βδ(t−B)，引入到达统计量 q_B+/μ/σ |
| E | minimax + 对偶 | 稳健化 → 拉格朗日 → 有界性条件 → 二阶导得 ODE → 指数解 p(t) |
| F | 线性规划 | 两层顶点枚举 → 4 个候选成本 → 策略四选一 → CDF 逆采样 |
| G | 算法 LUA | 主循环 + ComputeStrategy |
| H | 复杂度 | O(层数)，实测单次决策约 1 ms |

**发现的论文问题**：正文写 `D_i = Σ_{i'≥i} d_i'`，应为 `Σ_{i'>i}`。状态 s_i 已保留第 i 层，
只需重载其后的层；且只有 `>i` 才能复现 TABLE I 的成本数字。判为正文笔误。

### 阶段二：单 GPU 系统建模复现（至 2026-07-22 前后）

# 第二部分 · 系统建模详解（重点）

## 2.1 场景与实体

**一句话**：单用户随机产生多类异构 LLM 推理任务（需要不同模型），系统有 M 台距离不同的
边缘/云服务器（各存完整模型、显存有限）。需**联合决定**：① 任务路由到哪台 ② 各服务器各模型的层何时卸载。

### 实体与符号

| 符号 | 含义 | 取值（默认算例） |
|---|---|---|
| 用户 | 单个，按概率随机产生任务 | 1 个 |
| M | 服务器数，m=1 最近、m=M 为云 | 3 |
| K | 系统中不同 LLM 的个数 | 3 |
| N_k | 模型 k 的层数 | 34 / 26 / 8 |
| C̄ | GPU 显存容量，**各服务器相同** | 24000 MB |
| f_m | 算力（GFLOP/ms），**各服务器不同** | 6 / 12 / 30 |
| β_m | 存储→GPU 带宽（MB/ms） | 3.088（各服务器相同） |
| ℓ_m | 用户到服务器距离（m） | 100 / 250 / 400 |
| δ_m | 单向回程/传播时延（ms） | 1 / 8 / 40 |
| λ_k | 类型 k 任务的到达率（每时隙） | 0.06 / 0.15 / 0.30 |
| τ | 时隙长度（ms） | 100 |

### 7-31 组会逐条确认的设定

| 维度 | 设定 |
|---|---|
| 用户 | **单用户**，按概率随机产生任务 |
| 任务异构性 | ① 需要**不同的模型**（K 个）② **到达率不同** λ_k |
| 模型放置 | 每台服务器存**完整**模型，不拆层；任务在一台服务器上跑完 |
| 显存 | 各服务器**容量相同** C̄，但 **K 个模型共享**（新增耦合） |
| 算力 | 各服务器**不同**（云强边缘弱） |
| 通信 | 无线速率 R_m + 回程时延 δ_m，越远越大 |
| 智能体 | ★**用户 1 个 + 服务器 M 个**（异质）：用户决路由（每时隙）、服务器决层保留（每 Δ 时隙） |
| 目标 | min 推理时延 + 内存成本 − Jain 公平（负载均衡） |
| "搬运成本" | = 任务数据上传/回传，**就是传输时延本身**，不是独立第 4 项 |

## 2.2 单服务器内核（= 论文原模型）

论文原本针对单服务器单模型。这一节的模型在新场景里**原样复用为每台服务器的内核**，
只是每台服务器要同时管 K 个模型。

### 2.2.1 层结构与保留状态

模型 k 有 N_k 层，第 i 层占内存 `c_{k,i}`，重新加载耗时 `d_{m,k,i} = c_{k,i} / β_m`。

**保留状态** `s_{m,k} ∈ {0,…,N_k}`：第 1..s 层常驻显存、第 s+1..N 层已卸载。
层按"越靠前越先用到"排序（embedding → transformer × n → fc），卸载从尾部开始。
状态转移 `s → s−1` 即卸载第 s 层。

### 2.2.2 两个派生建模量（冲突的数学根源）

```
C_{k,s}   = Σ_{i≤s} c_{k,i}                    内存占用，随 s 递增
D_{m,k,s} = Σ_{i>s} d_{m,k,i}
          = (C_{k,N_k} − C_{k,s}) / β_m        重载延迟，随 s 递减
```

**C 递增、D 递减 —— 这就是内存与延迟两目标冲突的根源。**

> ⚠ 用 `>s`（不含第 s 层）。论文正文写 `≥i` 是笔误：状态 s 已保留第 s 层，只需重载其后的层；
> 且只有 `>i` 才能复现 TABLE I 的成本。

### 2.2.3 QoS 约束与最少常驻层数（论文式 1a 的 per-model 版）

任务类型 k 要求加载延迟不超过 `D^QoS_k`。由 D 递减：

```
i_check_{m,k} = min{ s | D_{m,k,s} ≤ D^QoS_k }
t_{m,k,i} = +∞    (1 ≤ i ≤ i_check_{m,k})     即前 i_check 层必须常驻
```

可卸载层为 `i_check+1 .. N_k`。

**实测值**（各服务器相同，因 β 相同）：

| 模型 | N | QoS (ms) | i_check | 最小常驻内存 (MB) | 可卸层数 |
|---|---|---|---|---|---|
| Qwen-7B | 34 | 2500 | **17** | 7364 | 17 |
| Qwen-1.8B | 26 | 700 | **8** | 1045 | 18 |
| Tiny | 8 | 150 | **0** | 0 | 8 |

### 2.2.4 ski-rental 临界点 B（数学钩子）

论文的关键假设 `d ∝ c`（TABLE III 实测 d/c ≈ 0.32 ms/MB 基本恒定）。此假设下所有"停在某状态"的
成本直线交于同一点：

```
B_{m,k} = η · D_{m,k,i_check} / (C_{k,N_k} − C_{k,i_check}) = η / β_m     （与模型无关！）
```

> 代码算出 **B = η/β 对所有模型相同** —— **自动复现了论文 C 节"d=kc ⇒ 所有直线交于同一点 B=ηk"的结论**。
> 在 TABLE I 配置（β=1, η=30）下 B = 30，与论文一致。
> B 仅作**数学钩子**暴露（将来约束 DRL 动作空间），不用于在线决策。
>
> ⚠ **η 不是自由参数**：它必须等于目标函数的 $\omega_1/\omega_2$，否则 B 不是本目标的真实
> break-even 点。对抗性审查曾发现代码用独立的 η=30 而目标用 $\omega_1/\omega_2=10^4$，
> **相差 333 倍**；已修复为由目标权重统一注入，当前默认算例下 **B = 3238.3 ms**。

## 2.3 新增耦合：K 个模型共享显存 ⭐（相对论文最主要的新增）

论文只有 1 个模型。新场景中一台服务器托管 K 个模型，它们**共享同一块显存**：

```
Σ_{k∈K} C_{k, s_{m,k}(t)}  ≤  C̄          ∀m, t          （约束 C3）
```

由此派生两个**论文里不存在的可行性条件**：

```
(a) 服务器可行：       Σ_k C_{k, i_check_{m,k}}  ≤  C̄
(b) 能服务模型 k：     C_{k,N_k} + Σ_{k'≠k} C_{k', i_check}  ≤  C̄
```

**(b) 的含义**：服务模型 k 时必须把它恢复到**全常驻**，其余模型最多只能压到各自的 i_check。
若不满足，该服务器根本无法服务该类任务。

> ⚠ **潜在缺口**：K 较大或显存紧时 (a) 很容易被违反。代码引入**放置变量** `y_{m,k} ∈ {0,1}`
> （`hosts` 掩码，某服务器不托管某些模型）处理。已有测试：8 GB 显存下正确报告"无法服务 7B 模型"。
> **此假设待导师确认。**

## 2.4 多服务器扩展

### 2.4.1 决策变量与双向耦合

| 变量 | 含义 |
|---|---|
| `x_{j,m} ∈ {0,1}` | **任务路由**：任务 j 是否由服务器 m 服务（Σ_m x_{j,m} = 1） |
| `t_{m,k,i}` | **层卸载时刻**：服务器 m 上模型 k 第 i 层何时卸载 |

**双向耦合（问题的核心结构）**：路由决定每个「服务器 × 模型」看到的有效到达率

```
λ_{m,k} = lim (1/T) Σ_{j: k_j=k} x_{j,m}
```

而 λ_{m,k} 决定该组合的最优卸载时机；反过来，当前保留状态 s_{m,k}(t) 决定把任务分给它是否划算。

### 2.4.4 内存成本与负载均衡

```
内存成本   Φ = Σ_m Σ_t Σ_k C_{k, s_{m,k}(t)} · τ            （内存占用 × 占用时长）
服务器负载 L_m(t) = Σ_{j:t_j≤t} x_{j,m}(T^ld + T^cp)          （累计占用时间，含加载+计算）
Jain 公平  F = (Σ_m L_m)² / (M · Σ_m L_m²)  ∈ [1/M, 1]
```

F = 1 表示完美均衡；F = 1/M 表示全部集中在一台。（沿用毕设做法，可直接复用经验。）

### 2.4.5 联合优化问题（完整形式）

```
 min                ω₁ · Σ_j T_j  +  ω₂ · Φ  −  ω₃ · Σ_t F(t)
{x_{j,m}}, {t_{m,k,i}}
             └ 时延 ┘   └内存成本┘   └负载均衡┘

s.t.  C1: Σ_m x_{j,m} = 1,  ∀j                    每个任务恰好一台服务器
      C2: x_{j,m} ∈ {0,1}                          二进制路由
      C3: Σ_k C_{k,s_{m,k}(t)} ≤ C̄,  ∀m,t         共享显存（新增）
      C4: s_{m,k}(t) ≥ i_check_{m,k}               QoS 最小常驻
      C5: t_{m,k,i} = +∞,  i ≤ i_check_{m,k}       常驻层永不卸
      C6: T_j ≤ T^max_{k_j}                        端到端 deadline
      C7: R_m(t) ≥ R^min                           最小链路速率
```

**问题性质**：含二进制路由变量、非凸速率表达、状态相关的加载延迟 ⇒ **混合整数非线性规划**；
且未来到达未知 ⇒ **在线**决策问题。

> 目标用 Σ_j T_j 与 Σ_t F(t)（而非平均值），是为了与 MARL 环境的**逐时隙奖励精确对应**。

## 2.5 多智能体 MDP

按组会"各服务器需作为智能体"，建模为**部分可观测马尔可夫博弈**，集中训练分布执行（CTDE）。

### 2.5.1 观测（每 agent 8 + 7K 维 = 29 维，K=3）

**全局部分（7 维）**：

| # | 分量 | 归一化 |
|---|---|---|
| 1 | 时隙进度 t / T | [0,1] |
| 2 | 自身显存利用率 | 占用 / C̄ |
| 3 | 自身相对负载 | L_m / Σ L |
| 4 | 上一时隙 Jain F | [1/M, 1] |
| 5 | 自身链路速率 R_m | / max R |
| 6 | 自身回程时延 δ_m | / max δ |
| 7 | 自身算力 f_m | / max f |

**每模型部分（7 维 × K）**：

| # | 分量 | 说明 |
|---|---|---|
| 1 | s_{m,k} / N_k | 该模型保留比例 |
| 2 | 空闲时长 | 该模型多久没被用 |
| 3 | i_check / N_k | **数学钩子**：QoS 下界 |
| 4 | B_{m,k} | **数学钩子**：ski-rental 临界点 |
| 5 | 全局到达率 λ_k | 估计值 |
| 6 | 局部到达率 λ_{m,k} | **路由耦合的载体** |
| 7 | 能否服务 (0/1) | 可行性掩码 |

**全局状态** s(t) = 各 agent 观测拼接（CTDE 的 Critic 用）。

### 2.5.2 动作（每 agent 2K 维 = 6 维，连续 ∈ [−1,1]）

```
φ_{m,k} ↦ 目标保留层数  s_tgt = i_check + ⌈(φ+1)/2 · (N_k − i_check)⌉   【只允许卸载】
          φ = −1 → 压到 i_check（QoS 底线）；φ = +1 → 全保留
ς_{k,m} ↦ 用户对"类型 k 任务去服务器 m"的偏好；m* = argmax_{可服务 m} ς_{k,m}  ⇒  x_{j,m*} = 1
（★2026-08-21 组会：原为服务器竞价 v_{m,k}，已被驳回 —— 路由归用户）
```

> 离散选择用**连续松弛**处理（沿用毕设信道选择的技巧），动作空间保持全连续，便于扩散策略输出。
> QoS 约束 C4/C5 **由动作映射的下界硬保证**（永远不会违反）。
> ★原先这里是"竞价、最高出价者得"（我们自选的冲突消解规则）。
> **2026-08-21 组会驳回**：路由由**用户**决定，用户本身是一个智能体；服务器只决定卸载哪些层。
> 而且两者**时间粒度不同**（用户每时隙、服务器每 Δ 时隙）—— 详见 `系统建模整理-多服务器.md` 第 3 节。

### 2.5.3 奖励

```
r_m(t) = − ω₁ · Σ_{自己服务的任务} T_j
         − ω₂ · Σ_k C_{k,s_{m,k}(t)} · τ
         + ω₃ · F(t) / M                        （Jain 为团队共享信号，除 M 使团队和 = ω₃F）
         − ω₄ · Ξ_m(t)                          （违规惩罚：显存越界 / QoS / deadline / 无可服务节点）
```

**关键性质（已断言，误差 < 1e−6）**：

```
Σ_m Σ_t r_m(t)  ==  − J        （J = 目标函数）
```

一个 episode = `horizon_slots` 个时隙的**连续到达过程**（不再是单个空闲期）。

| 12 | `eta` | 权重自洽：η = ω₁/ω₂，B = η/β = 3238.3 ms；TABLE I 退化算例 B=30 不变 | ✅ |
| 13 | `envconsist` | 三种策略下累计奖励 = −J（误差 < 1e−6） | ✅ |

**两个最有力的正确性证据**：
1. 新的多服务器模型在退化配置下**精确复现论文 TABLE I 四个成本**；
2. MARL 环境**团队累计奖励 == −目标函数 J**。
