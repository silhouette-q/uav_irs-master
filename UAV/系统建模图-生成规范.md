# 系统建模主图生成规范（半写实场景贴图版）

## 1. 目标

绘制一张用于顶会/IEEE 风格论文的系统建模主图，说明：单用户产生多类异构 LLM 推理任务，经无线链路路由到近端接入服务器、中端边缘服务器或远端云服务器；各服务器存有完整模型，并独立执行模型层卸载与任务接入决策。

图的核心不是展示公式细节，而是让读者一眼看懂：**任务路由、服务器异构性、模型显存状态，以及路由与层卸载的联合决策关系。**

## 2. 已确定的总体结构（不可改变）

- 左侧：单个用户与异构任务来源。
- 中部：三条由用户扇出到右侧服务器的无线链路。
- 右侧：三台服务器自上而下排列。
  - Server 1：Access server / near edge。
  - Server 2：Edge server / mid edge。
  - Server 3：Cloud server / far distance。
- 服务器按“距离和传输时延从上到下递增”排列。
- 每台服务器旁或下方放置一个 GPU 显存“图中图（picture-in-picture）”小卡片；由服务器场景贴图引出箭头连接到该卡片。
- 右侧若保留联合决策模块，其内容与物理系统区分清晰：任务路由、层卸载、状态更新、时延/内存/Jain 公平度。

## 3. 视觉风格（最高优先级）

### 3.1 必须采用：参考图式半写实场景贴图

整体风格应接近用户给出的 UAV-assisted MEC 顶会系统图：

- **半写实科研插画**，不是扁平化 icon infographic，也不是照片拼贴。
- 每一层/每个服务器都应包含小型真实场景：建筑、机柜、基站、道路、绿地、用户、移动设备等。
- 场景具有轻微俯视/等距视角（isometric 或 2.5D perspective）、自然投影、细节纹理与适度立体感。
- 场景放置在柔和的椭圆/圆角平台或地面上，具有“分层系统架构”的视觉语言。
- 用干净的细边框、少量虚线和箭头承载信息；不要用大量大矩形框代替场景。
- 所有文字、数学符号、箭头、显存条和图例必须后期以矢量方式叠加；**不要要求图像模型生成文字**。

### 3.2 禁止的风格

- 禁止纯色矩形框加简单图标的扁平 PPT 风格。
- 禁止卡通儿童插画、夸张 3D、赛博朋克、游戏 UI、霓虹发光。
- 禁止大面积深色背景、强渐变、复杂纹理背景。
- 禁止把服务器画成三个完全相同的通用机柜图标。
- 禁止在贴图内部生成难以校对的英文、数字、公式、Logo 或水印。

## 4. 配色规范（对齐参考图）

使用低饱和、浅色、白底的学术配色。推荐色值可作为后期矢量叠加的基准：

| 对象 | 建议颜色 | 用途 |
|---|---|---|
| 用户/无线接入层 | 浅蓝 `#DCECF8` | 用户场景、无线链路区域、近端接入场景 |
| 边缘服务器层 | 浅灰 `#E8E8E8` | 中端边缘机房场景 |
| 云/远端层 | 浅绿 `#E2F2DA` | 云数据中心地面/远端场景 |
| QoS 强制常驻层 | 柔和橙 `#F0A04B` | GPU 显存条中的 pinned layers |
| 可卸载但当前常驻层 | 学术蓝 `#2C6A9B` | GPU 显存条中的 resident layers |
| 已卸载层 | 浅灰 `#E8ECEF` | GPU 显存条中的 unloaded layers |
| 控制/反馈箭头 | 绿色 `#4F9270` | 可选的控制消息、状态反馈 |
| 无线任务链路 | 蓝灰 `#627F93` | 虚线数据传输箭头 |

## 5. 场景贴图内容

贴图统一采用相同镜头、光源和插画笔触，白色或可去除的纯色背景，**不含文字**。

### 5.1 左侧：用户任务源贴图

需要包含：

- 1 名用户，手持手机/平板或笔记本；
- 可在旁边出现轻量的家庭、校园或城市步道背景；
- 手机上的任务请求可用抽象的数据粒子/无线波纹表示；
- 不放服务器机柜，不放文字标签。

### 5.2 右上：接入服务器（near edge）贴图

需要包含：

- 小型无线接入站、蜂窝基站或路侧接入点；
- 紧邻的紧凑 MEC 机柜/边缘计算盒；
- 可有少量建筑、道路、树木作为近端城市环境；
- 强调“离用户近、通信快、计算较弱”。

### 5.3 右中：边缘服务器（mid edge）贴图

需要包含：

- 城市边缘微型数据中心或园区机房；
- 若干服务器机柜、通信塔/光纤接入、周边建筑；
- 尺度和资源量介于接入服务器与云数据中心之间。

### 5.4 右下：云服务器（far distance）贴图

需要包含：

- 更大规模的数据中心建筑或多排机柜；
- 可有云朵、远端城市天际线等弱提示；
- 强调“计算能力强、距离远、传输时延高”。

## 6. GPU 显存“图中图”设计

每台服务器都配一个独立的小型 GPU 显存状态卡片，放在服务器场景的左下方或下方外侧：

1. 卡片先画小显卡/GPU 图标（深灰外壳、少量金属/接口细节）。
2. 从服务器场景中机柜或计算设备位置，引出细而明确的箭头，指向 GPU 卡片。
3. 在 GPU 卡片中使用横向分段显存条，表示三个模型的共享显存状态。
4. 显存条颜色固定为：
   - 橙色：QoS-pinned layers；
   - 蓝色：resident, unloadable layers；
   - 浅灰：unloaded, reload on demand。
5. 三台服务器应展示不同状态：
   - Server 1：大部分模型常驻；
   - Server 2：部分模型卸载；
   - Server 3：更激进卸载，仅保留 QoS 必要层或按需重载。
6. 文字由后期矢量层添加：`Σ_k C_{k,s_{m,k}} ≤ C̄`、`GPU memory state` 等。

## 7. 图中数据与文字（由矢量层添加）

### 7.1 用户侧

- `User`
- `heterogeneous inference tasks`
- `type 1 → model 1, λ₁ = 0.06`
- `type 2 → model 2, λ₂ = 0.15`
- `type 3 → model 3, λ₃ = 0.30`

### 7.2 服务器侧

| 服务器 | 标题 | 参数 |
|---|---|---|
| 1 | `Server 1 (near edge)` | `f₁ = 6 GFLOP/ms`, `R₁ = 225.8 Mbps`, `δ₁ = 1 ms` |
| 2 | `Server 2 (mid edge)` | `f₂ = 12 GFLOP/ms`, `R₂ = 146.7 Mbps`, `δ₂ = 8 ms` |
| 3 | `Server 3 (cloud)` | `f₃ = 30 GFLOP/ms`, `R₃ = 106.6 Mbps`, `δ₃ = 40 ms` |

### 7.3 图例

- `pinned by QoS`
- `resident, unloadable`
- `unloaded (reload on demand)`
- `increasing distance / transmission delay`

## 8. 推荐生成流程

1. 生成四张无文字、统一风格的半写实场景贴图：用户、接入服务器、边缘服务器、云服务器。
2. 检查四张贴图的镜头、光照、颜色和细节密度是否一致；不一致时仅重生成不一致的那张。
3. 去除或抠掉纯色背景，保留完整场景主体。
4. 在 SVG/Illustrator/Figma/PowerPoint 中按“左用户、右三服务器”的结构排版。
5. 后期叠加无线虚线箭头、GPU 显存小窗、数学符号、英文标题和图例。
6. 输出 PDF/SVG 作为投稿版，PNG（≥300 dpi）作为预览版。

## 9. 可直接复用的图像生成提示词

### 9.1 通用风格前缀

```text
Use case: scientific-educational
Asset type: scene insert for a top-tier conference system-model figure
Style/medium: semi-realistic scientific illustration, polished 2.5D isometric perspective, detailed but restrained, consistent soft daylight, clean edges, subtle shadows
Color palette: white background, pale sky blue, light gray, soft green ground, muted realistic building and equipment colors; visually consistent with an IEEE/MEC architecture figure
Constraints: no text, no letters, no numbers, no labels, no logos, no watermark, no infographic panels, no UI, no border; leave generous whitespace around the subject for later vector annotations
Avoid: flat icon style, childish cartoon, cyberpunk, neon, dark background, photorealistic people close-up, clutter
```

### 9.2 用户场景

```text
Primary request: a single mobile user holding a smartphone, standing in a small realistic urban-campus or residential outdoor scene, subtle wireless signal waves and tiny abstract data particles near the phone, a few trees and pathway details, viewed in a gentle isometric 2.5D angle. The user and phone are the focus; no server racks or text.
```

### 9.3 接入服务器场景

```text
Primary request: a near-edge mobile access site: a compact cellular base station with antenna panels, a small roadside or rooftop MEC cabinet, a few nearby low-rise buildings, road and trees, conveying low-latency local access. Gentle isometric 2.5D scientific illustration.
```

### 9.4 边缘服务器场景

```text
Primary request: an edge computing site in an urban district: a compact micro data center building with visible server racks through a cutaway or open side, one communication tower, surrounding mid-rise buildings, road and greenery, conveying medium-scale computing capacity. Gentle isometric 2.5D scientific illustration.
```

### 9.5 云服务器场景

```text

```

## 10. 质量验收清单

- [ ] 一眼能辨认用户、接入服务器、边缘服务器、云服务器。
- [ ] 四张场景贴图视觉语言一致，且均没有文字或 Logo。
- [ ] 用户始终在左侧，服务器始终在右侧并上下排列。
- [ ] GPU 小卡片从对应服务器场景引出，具有明确的“图中图”关系。
- [ ] 显存条色义在三台服务器间一致。
- [ ] 近端到云端的距离、时延递增关系可由布局和链路标签读出。
- [ ] 图在缩小到双栏论文宽度时，主体与箭头仍清晰。
- [ ] 最终投稿版本提供 SVG/PDF，不只提供 PNG。
