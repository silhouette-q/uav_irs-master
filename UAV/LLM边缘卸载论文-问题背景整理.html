Efficient Layer-Granularity Unloading for LLMs in Edge Computing

一、这篇论文在解决什么问题

场景：在边缘服务器上用容器部署大模型（LLM）提供服务。边缘服务器 GPU 显存有限，而 LLM 请求是高度突发、稀疏的——有请求时要快速响应，没请求时模型就闲置在显存里。

核心矛盾：

  • 如果一直把模型留在显存里（persist retention）→ 响应快，但长期占用显存，内存成本高
  • 如果把模型卸载掉（unload）→ 省显存，但下次请求来了要重新加载，加载几十亿参数很慢（例：7B 模型从磁盘加载到 GPU 约 4800 ms），会违反 QoS
创新切入点：不再是"整个模型留 / 整个模型卸"这种粗粒度二选一，而是按层（layer）粒度决定——比如 5 层的模型，可以只保留 1-3 层、卸载 4-5 层。下次请求只需重载卸掉的那几层，加载延迟大幅降低。

二、决策变量（Decision Variables）

核心决策变量只有一个：每一层的"卸载时刻" ti

( t1, t2, …, t|ℐ| )
  • 模型有 |ℐ| 层，从模型进入空闲状态（t = 0）开始计时
  • ti = 第 i 层在空闲多久之后被卸载
  • 特殊情况：ti = +∞ 表示第 i 层永远保留在显存里

所以决策本质是回答两个问题："哪些层要卸载" + "什么时候卸载"（which layers to unload and when）。

论文用"保留状态 si"来简化描述：状态 si 表示第 1 到 i 层保留、其余卸载。决策 ti 就是从状态 si 转移到 si-1（再多卸一层）的时刻。

三、两个优化目标（Optimization Objectives）

论文把总成本定义为两项的加权和（对应公式 2a）：

目标 含义 变量记号
① 加载延迟 (loading delay) 下次请求到来时，重载卸掉的层所花的时间 Di
② 内存成本 (memory cost) 空闲期间保留的层占用显存 × 占用时长 Ci

优化目标（最小化）—— 论文原文式 (2a)：

min   ∑i∈ℐ∪{0} η Di Si(τ)  +  ∫0+τ ∑i∈ℐ∪{0} Ci Si(t) dt
（加载延迟的期望）      （内存成本的期望）

为了一眼看清 trade-off 的两项，可以把它简化成"某时刻确定处于某个状态 i"的直觉版：

min   η · Di(τ)  +  ∫0τ Ci(t) dt
（加载延迟）       （内存成本）
  • η 是权重（动机示例 TABLE I 中取 30），把"延迟"换算成和"内存成本"同一个量纲，方便加权求和
  • τ 是下一次请求到达的时刻（关键：这个是未知的、随机的）
  • Si(t) 是时刻 t 模型处于状态 si 的概率（第 1~i 层保留、其余卸载）

两个式子的区别联系

差别就在原文多出来的求和号 ∑ 和 Si(t)：

原文精确版 (2a) 直觉简化版
形式 对所有状态按概率 Si(t) 加权求和 → 期望值 假设确定处于单一状态 i
第一项 请求在 τ 到达时，各状态延迟成本 ηDi 按概率加权 = 加载延迟期望 当前状态的延迟 ηDi
第二项 每瞬间内存期望 ∑CiSi(t)，在 [0,τ] 积分 = 内存成本期望 当前状态内存 Ci 的积分
原文用 Si(t)：因为下次请求何时到达（τ）完全未知。论文把决策变量 ti 最终转成一个概率密度 P(t)，再和"对抗性"的到达时间做 minimax 博弈。所以目标必须写成对状态分布求期望的形式，才能顺理成章地取期望、推导后面的 ski-rental 问题。

当模型在时刻 t 确定处于状态 i 时，Si(t)=1、其余为 0，求和号消失 → 就退化成直觉版。两者物理意义一致，只是抽象层次不同。

配套的两个约束也印证了 Si(t) 是概率分布：

  • (2b) ∑i Si(t) = 1 → Si(t) 是合法概率分布（所有状态概率和为 1）
  • (2c) Si(t) = 0,  0 ≤ i ≤ ǐ−1 → 违反 QoS 的状态概率强制为 0（永不进入）

约束条件：QoS 约束——加载延迟不能超过阈值 DQoS。这决定了最少必须保留几层（记为 ǐ 层，第 1 到 ǐ 层必须常驻，否则一定违反 QoS）。

四、两个目标为什么冲突（关键中的关键）

保留的层越多 → 下次重载的层越少 → 加载延迟 ↓（目标①变好） → 但占用显存越多、越久 → 内存成本 ↑（目标②变差） 卸载的层越多 → 省显存 → 内存成本 ↓（目标②变好） → 但下次要重载更多层 → 加载延迟 ↑（目标①变差）

两个目标是此消彼长的关系。论文里有一句话点明了这个结构（系统模型部分）：

"内存占用越大的状态，加载延迟越小；反之亦然。"
即 C0 < … < C|ℐ|（保留越多内存越大）同时 D0 > … > D|ℐ|（保留越多延迟越小）

为什么难权衡：如果知道下一次请求什么时候来（τ），就能算出最优保留几层。但 τ 是未知的、不可预测的：

  • 如果请求很快就来，那就该多保留（省得重载，延迟小）
  • 如果请求很久才来，那就该早点卸载（省内存）

论文用了一个很直观的例子（TABLE I，5 层模型，每层 1s / 1GB，QoS ≤ 2s，权重 η=30；总成本 = 内存 + 30×延迟）：

  • 如果下次请求在 20s 后到（很快）→ 晚卸载 / 保留（t=30）最省，总成本 100；早卸载（t=10）反而最差，总成本 140
  • 如果下次请求在 35s 后到（很久）→ 早卸载（t=10）最省，总成本 185；晚卸载（t=30）最差，总成本 225
  • 同一个决策在不同到达时间下，成本高低完全相反 → 这就是决策困难的根源（τ 未知）
